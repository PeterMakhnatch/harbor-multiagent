# Verify a Harbor team's recorded decisions in CI

This is a consumer repository. It uses [SeatLab's public action](https://github.com/PeterMakhnatch/harbor-seatlab) by immutable commit, not a script copied into Harbor. The [workflow](../../.github/workflows/verify-seatlab-study.yml) imports no code from this repository. It needs no model, Docker service, or new Harbor run. GitHub downloads the pinned action and checkout. The verification itself runs offline.

The first study uses 2 native trials from one [published Harbor job](https://github.com/PeterMakhnatch/harbor-seatlab/blob/v0.11.0/examples/eval-lab/measured.md). There are 2 participants per trial. A single registered alignment check compares both roles. Three local input files suffice. `recorded-job/` does not contain raw chat, logs, authentication data, or executables. The [release](https://github.com/PeterMakhnatch/harbor-seatlab/releases/tag/v0.11.0) also contains small native result projections for stock Eval Lab's loader.

The correct trusted study pin is `f289c8c89a12bcb8c25753a8b3f5a5ac389825baceba874921e6e2587556110d`. The positive action emits a JSON summary and offline HTML. A separate negative control supplies another pin for the **same data**. The workflow requires that the second call fail and produce no outputs. Do not treat that expected refusal as a participant or task failure.

The second study uses [2 different native speaker–listener trials](https://github.com/PeterMakhnatch/harbor-seatlab/blob/v0.12.0/docs/observed-communication.md). The same 4 input files support 3 registered checks. All 20 listener moves match. The incoming signal first differs at world step 2. A nonexistent field is unknown on all 20 steps; those 20 accepted moves are still known. The workflow checks those measured outcomes, separately from checking the study digest. `observed-motion/recipe.json` shows the exact registered comparisons. The independently verified study pin is `a7c36b7a8d0a29f9b0002823e8b4003fa300330990fcafcbf7b561dcf08d8e55`.

To adopt the check, copy the positive workflow step, commit your sealed study with its inputs, and supply an independently trusted canonical study pin. Verification does not prove who generated the data. Protect your workflow and pin separately from unreviewed study updates.
