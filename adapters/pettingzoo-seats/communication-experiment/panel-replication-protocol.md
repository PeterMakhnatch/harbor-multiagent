# Independent Linux repeat of the selected regression panel

Selection and repetition answer separate questions. The whole first-attempt cohort uses 12 consecutive world seeds and 5 fixed teams per seed. The [registered forecast](held-out-pin.md) predicts all 60 trials before native collection. The [panel design](held-out-panel-design.json) declares 9 criteria over measured input, movement and missing evidence. We use that observed cohort to choose the fewest seed labels that witness all of its observed criteria. Break tied minima by sorted case label. This subset is not a new independent sample of worlds.

**Prospective replication rule.** Before inspecting the local cohort outcomes, register one fresh, standard Ubuntu GitHub runner on x86-64. If the algorithm selects between 1 and 3 seeds, run all 5 original teams on each selected seed. Otherwise do not run this bounded cross-platform repeat. Never substitute seeds, refill an unattempted cell, or choose a seed based on its payoff. A failure is a result. Use fresh task directories, native UUIDs and local simulator state. Neither a stored action nor an offline forecast is a native rerun. No model route, special hardware or secret is needed.

**Readouts.** Recompute the 9 criteria for the same selected worlds. Compare their witness, opposite and unknown states to the earlier observations. For every usable same-seed and same-team native pair, verify case identity and distinct trial identity. Report world order, exact accepted actions, exact private-view digests and per-role terminal returns to tolerance 1e-6. Count unique trials, not relation rows. If a numeric observation differs across architectures, report it without editing the source. An unknown or absent native game never counts as a match. Do not compare runtime on these unlike machines. The test does not establish that the panel detects unseen behavior changes or that it preserves a population estimate.
