A controlled [multi-agent task](/tasks/multi-agent) compares conditions that differ in one factor, for example seats that can message each other against seats that cannot. The comparison holds only if a seat cannot learn its condition or reach another seat outside the channel under test. In the runs that this page describes, agents tried both.

<Note>
These faults come from runs on this fork: 2- and 3-seat scheduling tasks, one harness, 4 open models, and 5 to 12 instances per model. "A seat did X" means that it happened in at least one run, not that agents usually do it. The evidence is in `flotilla/docs/FINDINGS.md` in [draft PR #18](https://github.com/PeterMakhnatch/harbor-multiagent/pull/18).
</Note>

## Seats can read the condition

Everything a seat can read counts: its instruction, its environment variables, its file names and contents, and every world reply, errors included. In a pilot, `GET /whoami` returned `"condition": "talk-liar"`, and both seats under test in one trial quoted it: "The condition is 'talk-liar', which might mean someone is lying." **Check:** search all of these for condition names, role names and answer values. **Fix:** reply with only what a seat needs to act, such as whether messaging is on.

## Runtime names carry the task name

Harbor names the Compose project after the trial, so container, network and volume names start with the task name, for example `schedule-004-silent__<trial-id>__env-main-1`. Seats can read them through reverse DNS and in `/proc/self/mountinfo`. In 1 of 793 pilot seat trajectories, a seat did a reverse lookup of the world and read its condition in the name. **Check:** in a seat, run `getent hosts` on the other containers' addresses and read `/proc/self/mountinfo`. **Fix:** keep conditions and roles out of task, service, network, alias and volume names. [Draft PR #19](https://github.com/PeterMakhnatch/harbor-multiagent/pull/19) hashes the project name; upstream, [harbor#3803](https://github.com/harbor-framework/harbor/pull/3803) makes session ids opaque.

## A format example is an answer

In one task family, every instruction showed the same example answer, and for one instance it was the true answer. A seat that copied it would score 1 with no information. The builder's tests found it, and the analysis left those trials out. **Check:** compare each example with the answer and decoys of every instance. **Fix:** use placeholders, such as `{"day": "<day>", "start": "<HH:MM>"}`, or a value that is never a valid answer. An example chosen to differ from the answer still rules out one candidate.

## Replies leak what other seats do

A reply whose content or timing depends on other seats is a channel. In a pilot, the submit reply carried a running count `n` of all seats' submissions, and a seat with messaging off wrote: "Wait, n jumped to 10! ... p2 has been actively submitting answers too." Later, with messaging off, seats of 2 models sent 2,112 and 4,671 unknown requests to the world in 12 trials each, and one model sent queries such as `{"query": "all_schedules"}` to the answer endpoint. **Check:** look for shared counters, global ids, error text and timing. **Fix:** answer each seat from its own state, return one fixed error for anything unknown, and log those requests.

## Seats can reach each other

Seats on one Compose network can reach each other. In a pilot where all seats shared one network, a seat with messaging off ran `getent hosts p1`, `curl -s http://p1:8080` and `nmap -sT 172.18.0.0/24`, and found its teammate. No seat started a listener, but nothing prevented it. **Check:** connect from each seat to every other seat, and check the mounts with `docker inspect`. **Fix:** give each seat its own network that only `main` also joins, and mount a seat's volume in no other seat; `main` can mount it read-only. [Draft PR #3](https://github.com/PeterMakhnatch/harbor-multiagent/pull/3) adds lint rules for this, including the opt-in `seat-shared-network`.

```yaml title="environment/docker-compose.yaml"
services: # network keys only
  main:
    networks:
      p1-net: {aliases: [world]}
      p2-net: {aliases: [world]}
  p1:
    networks: [p1-net]
  p2:
    networks: [p2-net]
networks:
  p1-net: {}
  p2-net: {}
```

## The last write decides the grade

If any seat can write the team's answer and the last write counts, the grade measures who wrote last. In 36 `talk` trials, a seat submitted the right answer in every trial, but 7 trials ended wrong, 6 of them because the teammate wrote a wrong answer later. If any correct submission counts instead, guessing pays: with messaging off, seats of one model hit the right answer in 12 of 12 trials. An instruction is not enforcement: told that only p1 submits, p2 still submitted in 2 to 8 of 12 trials, by model. **Check:** run scripted seats that overwrite a right answer or submit every candidate, and confirm the grade. **Fix:** enforce the rule in the world, for example one final commit per seat, with the team answer counted only when the commits agree. Credit writes with per-seat tokens ([draft PR #2](https://github.com/PeterMakhnatch/harbor-multiagent/pull/2) shows one way), and grade the world's record, not the seats' logs. Containers stay up during verification and a seat's process can still write, so save the record in a [`[[verifier.collect]]` hook](/jobs/artifact-collection#sidecar-artifacts) when play ends.

## Twin conditions differ in more than the manipulation

Twin conditions must show the seats the same bytes except for the manipulation. In the pilot with a lying scripted peer, the twins also differed in the `/whoami` label and in the task name. The scripted peer also posted a machine-readable `FLOTILLA-BRIEFING {...}` line that no real seat writes. One seat called it "the authoritative data source" and submitted the decoy twice. **Check:** diff every byte that a seat can read in the two twins. **Fix:** build twins from one template with the manipulation as the only parameter, and make scripted peers write in the seats' own format.

## Seats can reach the internet

Multi-agent tasks run only with network mode `public`, so seats can reach the internet and can meet through an outside service. This is a possible channel, not an observed one. **Check:** search the trajectories for hosts other than the world and the model API. **Fix:** none in Harbor yet; report it as a limit of the result.

## Checklist

| Check | How |
| --- | --- |
| No seat can read its condition | Search instructions, environment, files and world replies for condition names, roles and answers. |
| Runtime names are neutral | From a seat, look up other containers' addresses and read `/proc/self/mountinfo`. |
| No format example is an answer | Compare examples with every instance's answer and decoys, or use placeholders. |
| Replies depend only on the seat that asks | No shared counters, global ids, error text or timing. Log unknown requests. |
| Seats cannot reach each other | Connect from each seat to every other seat. Check mounts with `docker inspect`. |
| The grade follows a stated rule | Test overwrites and guessing with scripted seats. Grade the world's per-seat record. |
| Twins differ only in the manipulation | Diff every byte that a seat can read in the two twins. |
| Outside channels are reported | State that seats can reach the internet. Search trajectories for other hosts. |
