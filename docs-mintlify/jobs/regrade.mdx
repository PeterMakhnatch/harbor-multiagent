---
title: "Regrade"
description: "Run an updated verifier against recorded outputs without rerunning the agent."
---

<Note>
  Regrade is recommended when only the verifier changes and the task uses a
  separate verifier. The agent phase is not rerun.
</Note>

## Regrade a job

```bash
harbor job regrade "jobs/<job>" -p path/to/updated-task -e modal
```

`-p` accepts a task directory or a directory of tasks. Harbor matches tasks to
source trials by task name. Repeat `-p` to provide multiple locations.

## Regrade a trial

```bash
harbor trial regrade "jobs/<job>/<trial>" -p path/to/updated-task -e modal
```

The updated task must have the same name as the source trial's task.

## Regrade from Harbor Hub

Use a Hub job or trial UUID instead of a local path.

```bash
harbor job regrade deeac1d1-9588-422f-8d8a-d504ec9fae14 -p path/to/updated-task
harbor trial regrade 8f3c2a9e-1b4d-4c6f-9e2a-7d5b8c1f0a3e -p path/to/updated-task
```

## Requirements

- The source is a completed trial with readable `result.json` and
  `artifacts/manifest.json` files.
- The updated task uses a [separate verifier](/tasks/separate-verifier).
- Every artifact required by the updated verifier was collected by the source
  trial and still exists.

Using a separate verifier for the source task is a good practice because it
already grades from recorded artifacts. It is not required: a shared-verifier
source works if it recorded every input needed by the updated verifier.
Multi-step trials are regraded step by step and must keep the same steps as
the updated task.

Legacy artifact manifests do not record exclusion filters. When the updated task
declares exclusions, Harbor warns and continues regrading these records. Changes
to explicitly recorded filters still prevent regrading.

## Regrade a multi-agent trial

Run the original task in shared mode. If verification needs live state, export
it to a declared artifact before the original verifier starts. Do not use the
final contents of a writable artifact mount as a pre-verification snapshot.
Then edit the task for regrade:

```toml
[verifier]
environment_mode = "separate"
regrade_from_seat_record = true
```

Regrade starts fresh services. It does not restore the original live
environment. Harbor provides the verifier with these recorded files:

- Seat logs at `/logs/seats`.
- Files collected from the artifact mount at `/logs/artifacts`.
- Declared artifacts at their original `source` paths in the verifier
  environment. These paths contain copies of the recorded files, not live state.

For example, the verifier cannot query the original session from a database
service. Collect a dump during the original run and grade the dump instead.

The opt-in is your confirmation that the verifier grades recorded files.
Harbor does not check whether the verifier uses state from the new services.

The regrade task must keep the same seats and `under_test` flags. The source
must contain matching participants and `seat_results` in `result.json`, and a
`seats/<seat>/agent/` directory for every seat. The regrade participants and
any participant roster in source `config.json` or `lock.json` must agree with
`result.json`. Harbor compares participant settings as stored in JSON, not by
roster order. A missing file or an omitted roster is allowed for older
records. An unreadable file or an invalid roster prevents regrade.

Harbor refuses a source that records a failed log download for any seat.
Absent or null download status makes no completeness claim. Seat logs have no
integrity manifest. Harbor cannot prove that every log was collected or detect
changes to log contents.

Harbor warns when the task checksum or available lock digest changes.
In `result.json`, `source_task_checksum` identifies the task that ran the agents.
`task_checksum` identifies the task used for the fresh verifier.

Use `harbor trial regrade` or `harbor job regrade` without `--launch`.

## How it works

For each source trial, Harbor:

1. Copies the recorded outputs into a new trial.
2. Builds the updated verifier environment.
3. Runs verification and writes a new result.

No agent environment is started, so regrading needs no agent credentials and
incurs no new agent cost.

## Options

| Flag | Description |
| --- | --- |
| `-p, --task-path` | Local verifier task. Repeatable for jobs. |
| `-t, --task` | Registry verifier task for jobs. Repeatable. |
| `-d, --dataset` | Dataset of verifier tasks for jobs. Repeatable. |
| `-e, --env` | Verifier environment provider. Defaults to `docker`. |
| `--ve, --verifier-env` | Verifier environment variable. Repeatable. |
| `--verifier` | Custom verifier import path. |
| `--verifier-kwarg` | Custom verifier argument. Repeatable. |
| `-o` | Output parent directory. |

Job regrades also support `-n, --n-concurrent` and `--job-name`. Trial regrades
support `--trial-name`.
