# Seams pilot: protocol draft

Status: a draft for approval. Nothing here was run with a paid model. No spend is approved.
The plans are in `flotilla/plans/seams/`. The cost tables are in `pilot-forecast.md` (generated by
`flotilla/pilot_plan.py`). The runner is `flotilla/run_wave.py` with staged gates.

## 1. The question

For 2 frontier models of 2 providers: does the same work lose reward when it must cross a boundary between
agent contexts? If it does: is the loss the same when the reader is the model itself, does one sentence that
names the habit recover it, and does one harness mechanism recover it?

A pilot answers the first part only, for the families that pass the entry rule in section 2.

## 2. Entry rule: which families may enter a paid pilot

A family enters when all of this is true:
1. Its eval card has no failed check, and its oracle trials on Docker equal the simulator.
2. Two reviewers found no open BLOCKER or MAJOR item on the build that will run.
3. Live playtests with 2 frontier assistants (subscription CLIs) show a loss at the seam in 3 or more of 8
   live trials at one level, and the family's measures see that loss.

A family that every live trial passes at `standard` and `heavy` is at the ceiling for this model class. It
stays in the suite as a canary for smaller models. It does not enter a frontier pilot.

## 3. Models and harnesses

- Models: `openai/gpt-6.2-sol` and `anthropic/claude-opus-5.5`. Both have zero-data-retention endpoints in the
  public catalogue (read 2026-11-25).
- Harness 1: Terminus 2 through Harbor, as in the earlier Flotilla waves.
- Harness 2, later: one native command-line agent. A result that reverses between 2 harnesses retires the
  family (kill rule).
- Environment: Modal, or local Docker for the oracle stages.

## 4. Stages and gates (the runner enforces them; a person approves each stage)

| Stage | Cells | Gate to the next stage |
|---|---|---|
| A, control gate | The control arms (`solo`; `team-fullrecord` where the family has it) at each requested level; 10 instances per model | 9 of 10 full successes per model and level. A level that fails is void for that model and is dropped. |
| B, effect check | Each matched pair of arms (test arm and its control, same instances) at the first level that passed A; 12 pairs per model; staged exact McNemar at 3, 6 and 12 pairs | 2 or more control-only successes in 1 pair for 1 model. If no effect is seen with all 12 pairs valid, the family is "at the ceiling at this level"; the same check then runs at the next level that passed A. |
| C, headline | `team` against the primary control, with `hint` and `solo-seam` where the family has them; n pairs per model from the eval card's power plan, at most 100 | None. Fixed sample, exact McNemar, alpha 0.05, Holm correction per model. |

Run a stage with `python3 flotilla/run_wave.py <plan> --stop-after-stage A`, read the gate result, then resume
the same plan without the flag. Each stage has its own cumulative cap in the plan.

## 5. Outcomes

- Primary outcome of a trial: full success (`reward == 1`), or the family's declared `PRIMARY`.
- A seat's own omission (it stopped, refused, never handed over, never stepped) is a valid trial with a flag.
  It counts as a failure. The report gives the share of failures by flag, per arm.
- An infrastructure fault is invalid. The runner retries it once. It never counts.
- Pairing is by instance. The 3 costs are paired differences: boundary cost (control minus `team`), teammate
  cost (`solo-seam` minus `team`), protocol cost (`hint` minus `team`).
- Behaviour measures come from world events only (for example `stale_after_delivery`, `told_in_time`,
  `order_kept`). No LLM judge.

## 6. What the pilot cannot show

- No human baseline, no matched-token arm, no cross-model team (`team-x`). Each needs its own approval.
- One harness. The live playtests already showed that the harness changes behaviour: GPT-6 Luna passed the
  early-report task in the Codex CLI in 4 of 4 playtests, and failed it 32 of 32 times under Terminus 2.
- One harness. The live playtests already showed that the harness can change behaviour: in the Codex CLI,
  GPT-6 Luna opened its data files in 4 of 4 playtests and passed the false-report arm in 2 of 2; under
  Terminus 2 it failed that arm in 32 of 32 paid trials. The playtest numbers are too small for a comparison.
## 7. Kill rules

Retire a family for this model class when one of these is true:
- `team` scores 0.9 or more of its control at `standard`, and `hint` closes the rest.
- The effect reverses between 2 harnesses.
- A control arm is below 0.9 at `heavy`.

## 8. Cost

`pilot-forecast.md` has the table per family, per stage and per model, with low, expected and high values.
The estimate uses a turn model fitted on 2,679 finished seats of the earlier probe waves (in-sample error 36%
to 40%), 1 world call per model turn, and an uncertainty factor of 2. It is an upper envelope: every branch,
no early stop. A profile from playtest logs (`flotilla/token_profile.py --from-playtest`) replaces the turn
model when it exists. Stage A is the first decision: it costs the least and voids a level early.

## 9. Before any paid stage

1. Rebuild the tasks with a private seed and run `flotilla/qa.py`.
2. Run the plan's oracle stage on Docker ($0) and compare with the simulator.
3. Write the pre-registration section into `flotilla/docs/PROBE.md` and commit it before the first trial.
4. Set the cap of the stage. Check the key's limit. Check the zero-data-retention warning of the dry run.
